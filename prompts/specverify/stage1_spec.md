[단계 1: 사양 분석 — 요구사항 구조화]
아래 <기능사양서>만 근거로 요구사항을 구조화하라. 코드는 보지 않는다 (사양 해석이 코드에 끌려가지 않도록).

규칙
- 요구사항 단위로 분리한다. 원문에 ID가 있으면 그대로 쓰고 id_origin=SPEC, 없으면 "GEN-<S시작라인>" 형식으로 만들고 id_origin=GENERATED.
- source.quote에는 해당 요구사항 원문을 한 글자도 바꾸지 말고 그대로 복사한다 (라인 접두사 "Sxx| "는 제외). 검증 도구가 원문과 대조한다.
- 각 요소(입력·출력·실행 조건·판단 조건·상태·전이·타이머/카운터·임계값/경계·예외·우선순위)는 원문에 근거가 있을 때만 채운다. 각 요소의 quote에 근거 문구를 넣는다.
- 요소의 status: 원문에 명확히 정의 → DEFINED / 여러 해석이 가능 → AMBIGUOUS / 동작에 필요하지만 원문에 없음 → UNDEFINED.
- 임계값의 경계 포함 여부(이상/초과/이하/미만)를 inclusive에 정확히 반영한다. 원문 표현이 없으면 UNSPECIFIED.
- 시간 요구사항은 단위와 함께 적고, 주기 정보(예: 10ms)가 원문에 있으면 behavior에 "주기 기준 환산값"을 '추론'임을 밝혀 적을 수 있다.
- ambiguities: 해석이 갈리는 표현마다 이유와 사양 작성자에게 물어볼 질문을 적는다.
- undefined_items: 구현에 필요하지만 원문이 정의하지 않은 항목(무효값의 정의, 초기값, 상태 유지/초기화 여부 등)을 적는다.
- 개요·신호 표처럼 요구사항이 아닌 부분은 glossary/document_notes에 정리하고, 요구사항으로 만들지 않는다.
