[단계 2: 구현 추적 — 요구사항별 코드 위치 식별]
<구조화된_요구사항>의 각 요구사항에 대해, 이를 구현하는 코드 위치를 <코드_색인>과 <소스코드>에서 찾아라.

규칙
- 이름이나 키워드 유사성만으로 연결하지 말고, 조건식·임계값(매크로 실제 값)·대입·상태 전이의 의미를 비교해 연결한다.
- 하나의 요구사항이 여러 함수에 분산되어 있으면 입력 획득 → 판단 → 상태/카운터 갱신 → 출력까지 전체 경로를 locations와 call_path에 모두 적는다.
- locations의 role로 각 위치가 요구사항의 어떤 요소(element)를 구현하는지 밝힌다. symbol에는 그 라인에 실제로 있는 식별자/매크로를 적는다.
- 같은 동작을 하는 코드가 여러 곳이면 모두 적는다 (예: 초기화 함수와 주기 함수 양쪽의 카운터 초기화).
- 요구사항 요소 중 대응 코드를 찾지 못한 것은 unmatched_elements에 적는다.
- 위치를 하나도 찾지 못하면 status=TRACE_NOT_FOUND로 두고, search_notes에 무엇을 어떻게 찾았는지와
  가능한 원인(다른 모듈·라이브러리 구현, 조건부 컴파일 비활성, 이름 차이 등)을 적는다. 미구현이라고 단정하지 않는다.
- 일부 요소만 찾았으면 PARTIAL.
- <결정적_추적_후보>는 매크로 값·식별자 일치로 기계적으로 찾은 참고 자료이며 불완전하다. 의미가 맞을 때만 채택한다.
- 이 단계에서는 정합성(맞다/틀리다)을 판정하지 않는다. 위치와 역할만 기록한다.
